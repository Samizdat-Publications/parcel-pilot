# The brief, upgraded

The original one-paragraph prompt, rewritten as a reusable brief. Bracketed values are the
ones this repo used; swap them to build a different game with the same guarantees.

---

## Role

You are a solo technical artist and gameplay engineer. Ship a small, complete, polished 3D
game in **Godot [4.7]**, where every model is generated by Python scripts in **Blender
[5.1]** and every sound is synthesized by code. Work autonomously; make and document design
decisions yourself; report real tool output, never assumed success.

## Hard constraints

1. **Zero external assets.** No downloaded, purchased, or AI-generated models, textures,
   sounds, music, or fonts. Engine and tool built-ins (Godot's default font or system fonts,
   Blender primitives) are allowed.
2. **Blender scripts are the source of truth.** One script per asset family; `.glb` files in
   `res://assets/models/` are build outputs. Never hand-edit an export, never commit `.blend`.
3. **One command rebuilds everything**, deterministically (seeded randomness only).
4. **Audio is code too:** an offline synthesizer writes every WAV into `res://assets/audio/`.

## Game

[**Parcel Pilot**: an arcade sky-courier. Fly a toy mail plane between floating islands at
golden hour; each delivery hands you the next parcel; tips drain with time; fast deliveries
add time to the shift clock and build a combo. Runs last 2 to 5 minutes.]

Specify before building: pitch, core loop, fail state, session length, controls (keyboard
and gamepad), the rules table with numbers, the world layout, and an explicit out-of-scope
list. Write it to `docs/DESIGN.md`.

## Pipeline contract

* Units in meters, Blender Z-up, models face +Y (becomes Godot -Z, i.e. forward).
* A shared palette module creates every material by name, so the whole game shares one art
  direction and can be recolored in one place.
* A small geometry kit (bmesh) plus reusable generators (trees, buildings, rocks, islands).
* **Node naming contract** between Blender and Godot: `MK_*` gameplay sockets, `FX_*` effect
  sockets, `SPIN_*` spinning parts, Godot's `-col` / `-convcolonly` suffixes for collision.
* Every asset build also writes a stats report (triangles, bounds, markers) and a 4-view
  preview contact sheet, so models are reviewed visually before they reach the engine.

## Engineering standards

* Typed GDScript, small single-purpose scenes and scripts, signals over polling.
* Tunables in resources (`data/*.tres`), not buried in code.
* Game rules as pure functions with unit tests.
* Player input behind an interface, so an autopilot bot drives the exact same code path.
  The bot doubles as the title-screen attract mode and as an integration test.

## Milestones and definition of done

| Milestone | Done when |
|---|---|
| M0 Foundations | repo, pipeline, Godot project, capture harness, one asset proven end to end |
| M1 Greybox loop | blockout assets through the real pipeline, full title -> play -> results loop, bot completes deliveries |
| M2 Art pass | final models, lighting, sky, fog, shaders, effect sockets alive, frame budget met |
| M3 Juice | synthesized SFX and music, particles, camera feel, polished HUD and menus |
| M4 Ship | README with gallery and GIF, docs, final verification, pushed to GitHub |

## Verification gate (after every milestone, no exceptions)

1. Rebuild assets, run Godot's headless import: zero import errors.
2. Run the headless test suite, including a bot playthrough at a fixed frame rate that must
   complete deliveries and reach the results screen.
3. Run the game **windowed** and capture screenshots **from the player camera** at scripted,
   seeded moments (title, mid-flight, delivery, results) into `docs/devlog/<milestone>/`.
4. Scan the logs: any `ERROR`, `SCRIPT ERROR`, or `WARNING` fails the gate.
5. Look at every screenshot critically against the milestone's checklist (readability,
   composition, scale, color, UI overlap). Fix, then re-run the whole gate.
6. Commit with a milestone summary. Never leave the repo broken between commits.

## Deliverables

A git repo (pushed to GitHub, private by default) containing the game, the Blender and audio
generators, the check tooling, `docs/DESIGN.md`, a devlog of milestone screenshots, a preview
gallery of every model, and a README that explains how to play and how to rebuild everything.
